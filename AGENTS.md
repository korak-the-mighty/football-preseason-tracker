# AGENTS.md

## Mandatory start

Before doing any work in this repository, read these files in order:

1. `CORE.md`
2. `EXPERIENCE_CONCEPT.md`
3. `WORKFLOW.md`
4. `DATA_RULES.md`
5. `STATUS.md`

Treat them as the project memory. Do not silently contradict, duplicate or reopen their decisions.

## Operating rules

- Work on one clearly named problem at a time.
- Preserve the simple product. Extra features must not weaken the fixture-list core.
- Never invent, infer or “complete” football fixture data.
- Every fixture must comply with `DATA_RULES.md`.
- Separate strategy, data research and implementation work.
- Before changing scope, record the proposed decision in `STATUS.md`.
- When a durable decision is made, update the correct foundation file in the same change.
- At the end of a working session, update `STATUS.md` with what changed, what was ruled out and the single next action.
- Flag uncertainty explicitly. If uncertainty reveals a repeatable problem, improve the relevant rule rather than solving it differently every time.
- Do not claim the app is launched, complete or accurate until verification in `STATUS.md` supports that claim.

## Authority

Henrik owns the idea, taste, priorities and final decisions.

The AI working in the repository owns continuity, execution within the agreed scope, honest uncertainty and leaving the project easier for the next session.
